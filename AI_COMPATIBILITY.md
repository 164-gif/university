# Какие AI умеют нормально работать с University Notes

Обычный веб-чат и AI-агент с доступом к репозиторию — это не одно и то же.

Если модель работает только внутри браузерного чата, она может не открыть GitHub Pages, raw-файлы или несколько связанных URL. Поэтому для надёжной работы со **всем репозиторием** лучше использовать AI-инструмент, который видит локальную папку проекта или подключён к GitHub напрямую.

## Рекомендуется

### Qwen Code — подходит

**Статус:** ✅ рекомендуется.

Qwen Code — агент для терминала/IDE, который работает внутри папки проекта, читает структуру репозитория, ищет по файлам, запускает команды и может редактировать материалы.

Надёжный вариант:

```bash
git clone https://github.com/164-gif/university.git
cd university
qwen
```

После запуска можно написать:

> Прочитай `usethis.md`, `AGENTS.md`, `README.md` и правила репозитория. Затем подготовься отвечать по материалам University Notes.

Официально: https://github.com/QwenLM/qwen-code

Важно: **Qwen Code** и обычный **Qwen Chat в браузере** — разные режимы. Для всего репозитория предпочтителен именно Qwen Code.

### ChatGPT + GitHub — подходит

**Статус:** ✅ рекомендуется, если в ChatGPT подключён GitHub.

При наличии GitHub-коннектора ChatGPT может читать файлы репозитория напрямую и не зависит от того, способен ли обычный веб-браузер модели открыть GitHub Pages.

Достаточно указать репозиторий `164-gif/university` и попросить сначала прочитать:

- `usethis.md`;
- `AGENTS.md`;
- `README.md`;
- нужный `README.md` предмета;
- нужные материалы из `subjects/`.

Если GitHub не подключён, доступ по одной веб-ссылке зависит от возможностей конкретного режима ChatGPT.

### OpenAI Codex — подходит

**Статус:** ✅ рекомендуется.

Codex CLI/IDE работает с локальным клоном репозитория и может читать весь проект, искать файлы, изменять их и запускать команды.

```bash
git clone https://github.com/164-gif/university.git
cd university
codex
```

Официально: https://github.com/openai/codex

### Claude Code — подходит

**Статус:** ✅ рекомендуется.

Claude Code запускается внутри папки проекта и понимает кодовую базу/структуру файлов непосредственно с диска.

```bash
git clone https://github.com/164-gif/university.git
cd university
claude
```

Официально: https://github.com/anthropics/claude-code

Важно: обычный Claude Chat в браузере не следует считать эквивалентом Claude Code для этой задачи.

### Gemini CLI — подходит

**Статус:** ✅ подходит.

Gemini CLI работает с локальным контекстом проекта и может читать файлы и каталоги напрямую.

```bash
git clone https://github.com/164-gif/university.git
cd university
gemini
```

Официально: https://github.com/google-gemini/gemini-cli

Важно: если **Gemini Chat** в браузере пишет, что не может открыть нашу ссылку, это не означает, что Gemini CLI не сможет работать с репозиторием. CLI получает контекст из локальной папки.

### Cursor Agent — подходит

**Статус:** ✅ подходит.

Откройте клонированную папку `university` в Cursor. Agent умеет искать по кодовой базе, читать и менять файлы и выполнять команды.

Официально: https://cursor.com/docs

### GitHub Copilot coding agent — подходит

**Статус:** ✅ подходит при доступе к Copilot agent.

GitHub Copilot на GitHub.com может исследовать выбранный репозиторий, планировать изменения и работать с файлами репозитория. Это надёжнее, чем пытаться передать обычному чат-боту ссылку на GitHub Pages.

Официально: https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-on-github

## Может работать, но не стоит рассчитывать на одну ссылку

### Qwen Chat

**Статус:** ⚠️ зависит от режима и доступных инструментов.

Если веб-версия Qwen умеет открыть URL и переходить по ссылкам, `AI_ENTRY.txt` может сработать. Но это не гарантирует доступ ко всему репозиторию.

Для стабильной работы используйте **Qwen Code**.

### Gemini Chat

**Статус:** ⚠️ ненадёжно для этого способа.

В наших проверках Gemini Chat не смог стабильно открыть опубликованную AI-страницу. Поэтому не следует обещать, что одной ссылки будет достаточно.

Для всего репозитория используйте **Gemini CLI** или другой агент с локальным/GitHub-доступом.

### DeepSeek Chat

**Статус:** ⚠️ ненадёжно для этого способа.

DeepSeek смог прочитать часть входной страницы, но не смог стабильно открыть связанные материалы. Для работы со всем репозиторием обычный чат не рекомендуется.

Если DeepSeek используется внутри coding-agent оболочки, которая сама умеет читать локальные файлы, ситуация другая: доступ обеспечивает оболочка, а не браузер DeepSeek.

### Claude Chat

**Статус:** ⚠️ может зависеть от режима, загрузок и подключённых источников.

Для гарантированного доступа ко всему дереву файлов используйте **Claude Code**.

## Главное правило выбора

Для University Notes лучше выбирать не модель по названию, а **способ доступа к данным**.

Надёжные варианты:

1. AI работает прямо в локальной папке после `git clone`.
2. AI подключён к GitHub через официальный коннектор/agent integration.
3. AI coding agent сам клонирует репозиторий в облачную рабочую среду.

Ненадёжный вариант:

- отправить обычному чат-боту одну URL-ссылку и надеяться, что его встроенный браузер сможет последовательно открыть десятки файлов.

## Что выбрать обычному пользователю

Если нужен самый простой вариант:

- **ChatGPT + GitHub connector** — без локальной установки, если GitHub подключён;
- **Qwen Code** — хороший бесплатный/открытый вариант для работы из терминала;
- **Gemini CLI** — если хотите использовать Gemini, но браузерный Gemini не открывает ссылки;
- **Claude Code** — для Claude;
- **Codex** — для OpenAI coding-agent workflow;
- **Cursor** — если удобнее работать через IDE;
- **GitHub Copilot agent** — если хотите работать прямо через GitHub.

## Старт после клонирования

Для любого локального coding agent:

```bash
git clone https://github.com/164-gif/university.git
cd university
```

Первый запрос агенту:

> Сначала прочитай `usethis.md`, `AGENTS.md` и `README.md`. Затем изучи структуру `subjects/` и связанные инструкции. Не выдумывай отсутствующие данные. При ответах на тесты сначала ищи подтверждённые ответы в `exam/`, затем материалы преподавателя в `notes/` и `transcripts/`.

После этого агент получает доступ ко всему репозиторию через файловую систему и ему уже не нужен `AI_ENTRY.txt`.
