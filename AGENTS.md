# AGENTS.md — правила учебного репозитория

## Назначение

Репозиторий хранит исходные учебные материалы, дословные расшифровки, очищенные конспекты, краткие версии, определения, формулы и материалы для подготовки к зачётам и экзаменам.

Главный приоритет — достоверность. Красивый текст не важнее точного текста.

## 1. Главный запрет: не выдумывать

Никогда не подставлять «логичный» текст вместо того, что не удалось разобрать.

Использовать явные метки:
- `[неразборчиво]`
- `[неразборчиво, ~3–5 слов]`
- `[предположительно: ...]` — только если вариант действительно вероятен
- `[формула неразборчива]`
- `[имя/термин неразборчив]`
- `[пропуск в исходнике]`

Запрещено:
- выдавать догадку за точную расшифровку;
- восстанавливать фамилию, дату, число или формулу только «по смыслу»;
- добавлять сведения, которых преподаватель не говорил и которых нет в исходнике, без явной маркировки;
- смешивать дословную расшифровку и пересказ.

## 2. Разделение слоёв

Для одного материала могут существовать разные файлы:

1. `raw/` — исходник или информация о нём; не изменять.
2. `transcripts/` — максимально близкая к исходнику расшифровка.
3. `notes/` — очищенный учебный конспект.
4. `summaries/` — короткая версия для повторения.
5. `concepts/` — определения, формулы, термины и связи.
6. `exam/` — подготовка к зачёту/экзамену.

Нельзя заменять один слой другим.

## 3. Расшифровка аудио и видео

При наличии аудио:
- сохранять порядок речи;
- удалять повторы, слова-паразиты и посторонние реплики только в CLEAN-версии;
- не менять смысл;
- сохранять примеры преподавателя;
- таймкоды оставлять, если они доступны или полезны для проверки;
- длинные записи обрабатывать сегментами с естественными паузами;
- сомнительные места не «чинить» моделью — помечать.

Рекомендуемый pipeline:
`audio/video → RAW transcript → CLEAN transcript → учебный конспект → краткий конспект → exam/concepts`.

## 4. Фото рукописных конспектов

- Сначала определить порядок страниц.
- Читать страницу целиком, используя контекст соседних строк.
- Не доверять одиночному слову, если оно конфликтует с остальной записью.
- Формулы переписывать отдельно.
- Если часть формулы или обозначения не видна — не достраивать.
- Сохранять авторские сокращения, если их смысл не установлен уверенно.
- При восстановлении структуры не добавлять отсутствующие тезисы.

## 5. Формат полного учебного конспекта

Хороший конспект обычно содержит:
- тему и дату;
- структуру лекции;
- ключевые понятия;
- основные тезисы;
- определения;
- классификации и перечисления;
- формулы и обозначения;
- примеры преподавателя;
- важные замечания;
- блок «Что важно запомнить»;
- возможные вопросы к зачёту/экзамену;
- неясные места, которые стоит перепроверить.

## 6. Источники и внешние дополнения

Если пользователь просит только расшифровать материал — не добавлять внешние знания.

Если пользователь отдельно просит дополнить, проверить или объяснить:
- отделять информацию из исходника от внешнего дополнения;
- приводить источник для существенных внешних фактов;
- не переписывать исходный конспект так, будто дополнение было в лекции.

## 7. Obsidian

Markdown должен нормально читаться в Obsidian:
- понятная иерархия заголовков;
- короткие абзацы;
- списки для классификаций;
- таблицы только когда они реально удобнее списка;
- wikilinks — для устойчивых понятий и связанных лекций;
- callout-блоки — только для действительно важного;
- не превращать каждую строку в декоративный блок.

## 8. Работа агента

Перед созданием нового материала:
1. прочитать этот файл;
2. прочитать `docs/COHORT_STRUCTURE.md` и определить учебный набор;
3. прочитать профиль предмета, если он существует;
4. определить тип исходника;
5. сохранить различие RAW / transcript / note / summary / exam;
6. выполнить проверку по `docs/QUALITY_CHECKLIST.md`.

Правило размещения обязательно:
- **ИБ-2026 — 1 курс** → `subjects/<предмет>/...`;
- **ИБ-2025 — 1 курс** → `cohorts/ib-2025-1kurs/subjects/<предмет>/...`;
- **ИБ-2026 — 2 курс** → `cohorts/ib-2026-2kurs/subjects/<предмет>/...`;
- другие новые наборы → `cohorts/<id-набора>/subjects/<предмет>/...`.

Корневой `subjects/` является постоянным местом для ИБ-2026 — 1 курс. **Не переносить его** в `cohorts/ib-2026-1kurs/subjects/` без прямого отдельного решения пользователя.

Если профиль конкретного предмета противоречит общим правилам, профиль предмета определяет формат, но не может отменять запрет на выдумывание или правило размещения по учебным наборам.

## 9. Рисунки, схемы и визуализация

Если в исходном конспекте есть рисунок, схема, график, таблица, блок-схема или другой содержательный визуальный элемент, агент обязан перенести его в чистовой конспект.

Правила:
- рисунок из исходника восстанавливать максимально близко к смыслу оригинала;
- для схем и диаграмм предпочтителен SVG в `notes/assets/`;
- в Obsidian использовать embed вида `![[assets/имя.svg|720]]`;
- под восстановленной схемой указывать исходную страницу/файл;
- не дорисовывать неразборчивые подписи и элементы по догадке;
- если часть рисунка не читается, явно отметить это;
- точность важнее красоты.

Допускается добавить новую иллюстрацию, которой не было в исходнике, только если она заметно облегчает понимание материала. Такая иллюстрация должна:
- быть фактически достоверной;
- не противоречить исходному материалу;
- не содержать выдуманных деталей;
- быть явно помечена как **дополнительная иллюстрация**, а не как рисунок преподавателя.

Не добавлять декоративные картинки, которые не несут учебной пользы.

## 10. Проверка фактов без скрытого исправления

Если материал можно проверить по надёжным внешним источникам, агент должен проверять:
- термины и определения;
- даты и числа;
- формулы;
- фамилии и названия;
- аббревиатуры;
- законы, статьи и нормативные формулировки;
- классификации и другие проверяемые утверждения.

Главное правило: **не исправлять исходный конспект молча**.

Если найдено возможное противоречие, устаревшая формулировка, ошибка преподавателя, ошибка распознавания или сомнительный фрагмент:
1. сохранить исходную формулировку в transcript/note;
2. создать или обновить файл `checks/There might be a mistake.md` соответствующего предмета;
3. указать точное место ошибки;
4. привести исходный фрагмент;
5. объяснить, почему он вызывает сомнение;
6. написать, что, вероятно, нужно исправить;
7. указать уровень уверенности;
8. указать источник проверки.

Использовать формулировку **There might be a mistake**, если ошибка не доказана однозначно.

Подробная политика: `docs/FACT_CHECK_POLICY.md`. Шаблон: `templates/there_might_be_a_mistake_template.md`.
