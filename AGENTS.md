# AGENTS.md — правила учебного репозитория

## Назначение

Репозиторий хранит исходные учебные материалы, дословные расшифровки, очищенные конспекты, краткие версии, определения, формулы и материалы для подготовки к зачётам и экзаменам.

Главный приоритет — достоверность. Красивый текст не важнее точного текста.

## 1. Главный запрет: не выдумывать

Никогда не подставлять «логичный» текст вместо того, что не удалось разобрать.

Использовать явные метки:
- `[неразборчиво]`
- `[неразборчиво, ~3–5 слов]`
- `[предположительно: ...]` — только если вариант действительно вероятен
- `[формула неразборчива]`
- `[имя/термин неразборчив]`
- `[пропуск в исходнике]`

Запрещено:
- выдавать догадку за точную расшифровку;
- восстанавливать фамилию, дату, число или формулу только «по смыслу»;
- добавлять сведения, которых преподаватель не говорил и которых нет в исходнике, без явной маркировки;
- смешивать дословную расшифровку и пересказ.

## 2. Разделение слоёв

Для одного материала могут существовать разные файлы:

1. `raw/` — исходник или информация о нём; не изменять.
2. `transcripts/` — максимально близкая к исходнику расшифровка.
3. `notes/` — очищенный учебный конспект.
4. `summaries/` — короткая версия для повторения.
5. `concepts/` — определения, формулы, термины и связи.
6. `exam/` — подготовка к зачёту/экзамену.

Нельзя заменять один слой другим.

## 3. Расшифровка аудио и видео

При наличии аудио:
- сохранять порядок речи;
- удалять повторы, слова-паразиты и посторонние реплики только в CLEAN-версии;
- не менять смысл;
- сохранять примеры преподавателя;
- таймкоды оставлять, если они доступны или полезны для проверки;
- длинные записи обрабатывать сегментами с естественными паузами;
- сомнительные места не «чинить» моделью — помечать.

Рекомендуемый pipeline:
`audio/video → RAW transcript → CLEAN transcript → учебный конспект → краткий конспект → exam/concepts`.

## 4. Фото рукописных конспектов

- Сначала определить порядок страниц.
- Читать страницу целиком, используя контекст соседних строк.
- Не доверять одиночному слову, если оно конфликтует с остальной записью.
- Формулы переписывать отдельно.
- Если часть формулы или обозначения не видна — не достраивать.
- Сохранять авторские сокращения, если их смысл не установлен уверенно.
- При восстановлении структуры не добавлять отсутствующие тезисы.

## 5. Формат полного учебного конспекта

Хороший конспект обычно содержит:
- тему и дату;
- структуру лекции;
- ключевые понятия;
- основные тезисы;
- определения;
- классификации и перечисления;
- формулы и обозначения;
- примеры преподавателя;
- важные замечания;
- блок «Что важно запомнить»;
- возможные вопросы к зачёту/экзамену;
- неясные места, которые стоит перепроверить.

## 6. Источники и внешние дополнения

Если пользователь просит только расшифровать материал — не добавлять внешние знания.

Если пользователь отдельно просит дополнить, проверить или объяснить:
- отделять информацию из исходника от внешнего дополнения;
- приводить источник для существенных внешних фактов;
- не переписывать исходный конспект так, будто дополнение было в лекции.

## 7. Obsidian

Markdown должен нормально читаться в Obsidian:
- понятная иерархия заголовков;
- короткие абзацы;
- списки для классификаций;
- таблицы только когда они реально удобнее списка;
- wikilinks — для устойчивых понятий и связанных лекций;
- callout-блоки — только для действительно важного;
- не превращать каждую строку в декоративный блок.

## 8. Работа агента

Перед созданием нового материала:
1. прочитать этот файл;
2. прочитать профиль предмета, если он существует;
3. определить тип исходника;
4. сохранить различие RAW / transcript / note / summary / exam;
5. выполнить проверку по `docs/QUALITY_CHECKLIST.md`.

Если профиль конкретного предмета противоречит общим правилам, профиль предмета определяет формат, но не может отменять запрет на выдумывание.
