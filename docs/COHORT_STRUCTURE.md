# Структура учебных наборов

## Зафиксированное правило

Текущая структура `subjects/` **не переносится**. Она остаётся постоянным местом для материалов набора **ИБ-2026 — 1 курс**.

То есть все существующие материалы и все новые материалы именно для `ИБ-2026 — 1 курс` продолжаем писать сюда:

```text
subjects/<предмет>/...
```

Примеры:

```text
subjects/physics/...
subjects/analytical_geometry/...
subjects/obzh/...
subjects/information_security_fundamentals/...
```

Это сделано намеренно, чтобы не ломать существующие Obsidian `[[wikilinks]]`, ссылки на SVG/медиа, историю репозитория и старые пути.

## Новые учебные наборы

Все остальные наборы хранятся только в новой структуре:

```text
cohorts/<набор>/subjects/<предмет>/...
```

На данный момент используются:

```text
cohorts/ib-2025-1kurs/subjects/<предмет>/...
cohorts/ib-2026-2kurs/subjects/<предмет>/...
```

Пока эти наборы пустые.

## Куда писать новый материал

Перед созданием нового материала агент обязан определить учебный набор.

- Если материал относится к **ИБ-2026 — 1 курс** → писать в `subjects/<предмет>/...`.
- Если материал относится к **ИБ-2025 — 1 курс** → писать в `cohorts/ib-2025-1kurs/subjects/<предмет>/...`.
- Если материал относится к **ИБ-2026 — 2 курс** → писать в `cohorts/ib-2026-2kurs/subjects/<предмет>/...`.
- Для любого нового набора использовать `cohorts/<id-набора>/subjects/<предмет>/...`.

Нельзя самовольно переносить `subjects/` в `cohorts/ib-2026-1kurs/subjects/`.

## Структура предмета

Внутри каждого предмета сохраняется прежняя схема:

```text
<предмет>/
├── README.md
├── raw/
├── transcripts/
├── notes/
├── summaries/
├── concepts/
├── exam/
└── checks/
```

## Для сайта

Сайт логически отображает:

- `subjects/**` как **ИБ-2026 — 1 курс**;
- `cohorts/ib-2025-1kurs/subjects/**` как **ИБ-2025 — 1 курс**;
- `cohorts/ib-2026-2kurs/subjects/**` как **ИБ-2026 — 2 курс**.

Таким образом, физическая структура репозитория сохраняет совместимость со старыми материалами, а веб-интерфейс всё равно показывает единое разделение по курсам.
